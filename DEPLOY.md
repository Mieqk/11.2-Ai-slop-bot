# Паспорт деплоя (для админа хостинга)

Бот модерации Discord + Minecraft. **Обычное долгоживущее Python-приложение, а не
веб-сайт**: почти весь трафик — исходящий WebSocket к Discord; веб-хуков и
публичного HTTP-эндпоинта не требуется (кроме опционального health-порта, §4).

## 1. Что запускать
| | |
|---|---|
| Код | архив `discord-modbot.zip` (~150 КБ) → каталог приложения |
| Python | 3.10 – 3.13 (в `Dockerfile` — `python:3.12-slim`; собрано/проверено на 3.13) |
| Установка зависимостей | `pip install -r requirements.txt` (диапазоны) или **`pip install -r requirements.lock.txt`** (pin, §2) |
| Команда запуска | `python bot.py` (есть `Procfile`: `web: python bot.py`, и `Dockerfile`) |
| Точка входа | одна: `python bot.py`, фоновый процесс; HTTP-ручка одна — `GET /healthz` (§4) |
| Рабочая директория | должна быть записываемой для `./data/` (SQLite) |
| Сигналы | SIGINT/SIGTERM → корректный выход. Внутри есть супервизор переподключения; под systemd/Docker запускайте `python bot.py --once`, чтобы надзор был однорежимный |

## 2. Версии зависимостей (lock, 11 пакетов)
Прямые: **discord.py 2.7.1**, **aiohttp 3.14.3** (диапазон в `requirements.txt`:
`discord.py>=2.4`, `aiohttp>=3.9`). Транзитивные: aiohappyeyeballs
2.7.1, aiosignal 1.4.0, attrs 26.1.0, frozenlist 1.8.0, idna 3.19, multidict
6.8.0, propcache 0.5.2, yarl 1.24.5 — плюс **audioop-lts 0.2.2 только для Python
3.13+** (discord.py тянет его там, где `audioop` убрали из stdlib; на 3.10–3.12
строку из lock'а убрать). Lock = версии, на которых прогнаны офлайн-тесты;
свежий `pip install -r requirements.txt` может подтянуть более новые patch-релизы
(например multidict 6.8.0 вместо 6.7.1) — это тоже рабочая конфигурация.

Других нативных зависимостей нет: OpenSSL/`cffi`/`librosa`/Redis/Postgres —
не требуются. `PyNaCl` (голос) не нужен: бот не подключается к войсу, он
выдаёт таймауты/права. Полный список — `requirements.lock.txt`.

## 3. Переменные окружения
| Переменная | Обязательна | Значение |
|---|---|---|
| `DISCORD_TOKEN` | да | токен бота (Discord Developer Portal → Bot → Reset Token). Перекрывает `token` в `config.json`; файла с конфигом может не быть вовсе |
| `PORT` / `WEB_PORT` | нет | если заданы, бот поднимает `GET /healthz` на этом порту (`keepalive: "auto"`) |
| `MC_RCON_PASSWORD` | нет | только для `tools/mc_probe.py` |
| `TZ` | желательно | таймстемпы в карточках считаются Discord'ом, но логи удобнее в вашей зоне |

## 4. Порты и направления (главный вопрос)

### Исходящие (обязательные)
| Куда | Порт | Зачем |
|---|---|---|
| `wss://gateway.discord.gg` | **TCP 443** | WebSocket шлюза: события, команды, presence |
| `https://discord.com/api/v10` | **TCP 443** | REST: выдача мутов/банов, публикация карточек, sync команд |
| `cdn.discordapp.com` / `media.discordapp.net` | **TCP 443** | только когда админ грузит файл: `/rules import` читает вложение ботом (остальные картинки/аватары в карточках качает клиент Discord, не бот) |

### Входящие
| Откуда | Порт | Условие |
|---|---|---|
| внешний пингер / балансировщик хостинга | **TCP `$PORT`** (обычно 8080 внутри контейнера) | только если включён health (`keepalive: "auto"` при заданном `PORT`, либо `"true"` + `keepalive_port`). Нужен, чтобы бесплатный хостинг не усыплял контейнер. Отвечает `GET /healthz`, `GET /health`, `GET /` |
| **из Minecraft-сервера в бота — не надо ничего** | — | RCON client→server: бот сам устанавливает соединение |

### Исходящие к игре (только если включён RCON-драйвер)
| Куда | Порт | Примечание |
|---|---|---|
| `rcon.ip:rcon.port` Minecraft-сервера | **TCP 25575** (по умолчанию; берётся из `server.properties`) | правило фаервола ставится **на стороне игрового сервера**: разрешить вход с IP того хоста, где бот. Порт наружу не публикуем — протокол без шифрования и без rate-limit; по возможности держите в приватной сети/туннеле или на одной машине (`127.0.0.1`) |
| TCP 25565 (сама игра) | **не нужен** | бот не играет и не смотрит статус сервера |
| Discord voice (UDP 50000–65535, STUN) | **не нужен** | войс не используется |

### Формулировка для фаервола (пример)
```bash
# на хосте Minecraft: пускать только машину бота
ufw allow from 10.0.0.23 to any port 25575 proto tcp   # бот в приватной подсети
# либо, если бот на той же машине — rcon.ip=127.0.0.1 и правил не нужно
```

## 5. Health/ready
`GET /healthz` → JSON: `status` (`ok`/`starting`), `bot`, `gateway_latency_ms`,
`guilds`, `members`, `active_punishments`, `uptime_s`. HTTP-код **200**, когда
бот готов, **503** — пока подключается. Readiness-проба по `/healthz`, liveness
можно по коду 503 тоже не делать (503 — нормальное состояние старта).

## 6. Ресурсы и хранение
- ~40–60 МБ RAM на старте (один WebSocket-воркер, без кэшей), CPU почти 0; лимит
  `nofile` обычный.
- Диск: код ~1 МБ + `data/modbot.sqlite3` (сотни КБ на тысячи записей, растёт
  медленно). **нужен постоянный volume (том)**: без него при пересоздании контейнера теряются
  история наказаний, привязки ник↔Discord, тексты правил и настройки серверов
  (Discord-таймауты и баны живут на стороне Discord и не теряются).
- Логи — только stdout/stderr (перенаправляйте в journald/драйвер хостинга);
  файловых логов бот не пишет, `--verbose` включает DEBUG библиотеки.

## 7. Проверка после установки (по порядку)
```bash
python bot.py --check                       # конфиг и все команды (токен не нужен)
python test_offline.py                        # движок наказаний    -> 204/204
python test_features.py                        # правила/медиа/игра  -> 177/177
MC_RCON_PASSWORD='…' python tools/mc_probe.py  # связь с игрой (если RCON включён) -> код 0
curl -s localhost:8080/healthz                # {"status":"ok", "guilds":…}
```
В Discord: `/whoami` → права/драйвер/канал логов зелёные; `/ping`.

## 8. Обновление / откат
1. бэкап: `cp data/modbot.sqlite3 data/backup-$(date +%F).sqlite3` (или снапшот тома);
2. замена кода, **`config.json` и `data/` не перезаписывать**;
3. `pip install -r requirements.lock.txt`;
4. `python bot.py --check && python test_offline.py && python test_features.py`;
5. откат = вернуть предыдущий код + бэкап БД (схема добавляется через
   `CREATE TABLE IF NOT EXISTS`, миграций-версий нет, обратная совместимость
   колонок не ломается).

## 9. Что админу хостинга знать дополнительно
- бот **не** слушает веб-порт по умолчанию — деплой как `worker` корректен, но
  на фри-тарифах (Render/Railway) без `PORT` его усыпят; тогда деплойте как
  `web` + внешний пинг `/healthz` (или включите `keepalive: true`);
- супервизор внутри процесса переподключается сам (паузы 5→300 с, потолок
  900 с), поэтому systemd-`Restart=always` дублировать не обязательно; для
  systemd/Docker запускайте `python bot.py --once`, чтобы надзор был один;
- одновременно одной БД пишущих процессов быть не должно (`sqlite` lock);
- правка `config.json` и переменных требует рестарта процесса (конфиг читается
  на старте), настройки через slash-команды применяются сразу и хранятся в БД.
