# Полная инструкция: Discord-бот модерации для Minecraft-сервера

Это операционный manual: установка, первый запуск, связка с игровым сервером,
деплой, эксплуатация, диагностика, кастомизация. README.md остаётся обзором,
этот файл — «как руками».

Проверено на: Python 3.13 (в `Dockerfile` — 3.12-slim), discord.py 2.7, aiohttp 3.14.
Минимум — 3.10 (используются `X | None` в аннотациях run-time-выражений и
`asyncio.to_thread`). Рекомендуемая рабочая комбинация — 3.11–3.13.

---

## 0. Как это устроено

Один Python-процесс. Он подключается к Discord как ordinary bot и, если включено,
к консоли Minecraft-сервера по RCON. Плагином в Minecraft он **не** является.

```
bot.py                 запуск, супервизор переподключения, аргументы CLI
core/config.py         слияние config.json + переменных окружения (DISCORD_TOKEN)
core/db.py             SQLite: cases, mute_overwrites, guild_config, rule_categories, game_links
core/moderation.py     «как наказать»: timeout / роль / запреты по каналам / RCON
core/audit.py          карточки журналов и ЛС (BRANDING — тексты и цвета)
core/style.py          общий «домашний» стиль для правил и медиа-карточек
core/rules_repo.py     разделы правил + порезка текста на страницы
core/gamefeed.py       разбор строк лога/вывода RCON -> событие «наказали в игре»
core/keepalive.py      GET /healthz, чтобы хостинг не усыплял контейнер
core/timeutil.py       сроки: «1h30m» <-> «1 час 30 минут» <-> «1h30m» для плагина
core/helpers.py        разбор аргументов команд и защита «не трогай старших»
cogs/*.py              slash-команды: moderation, warns, records, rules, media,
                       voice (комнаты), gamefeed (события игры), expiry (авто-снятие)
drivers/*.py           «мут в игре»: discord_voice (seria deafen) и rcon (Source/MC RCON)
tools/mc_probe.py      диагностика RCON: порт, авторизация, вывод `list`
rules.example.json     шаблон текстов правил (можно импортировать как есть)
test_offline.py        204 проверки движка наказаний и реконнекта (без токена)
test_features.py       199 проверок правил, медиа, комнат, gamefeed
```

Что где хранится:
- **наказания, привязки ников, настройки сервера, тексты правил** — в SQLite
  (`data/modbot.sqlite3` + `-wal`/`-shm`). Если ФС эфемерная, всё это теряется при
  пересоздании контейнера — см. §7 про тома и бэкапы;
- **timeout/бан на стороне Discord** живут на серверах Discord и бота не требуют:
  выданный мут не «пропадёт», пока бот лежал;
- **тексты карточек и цвета** — в одном месте (`core/audit.py`, блок BRANDING),
  вайсбор стилей правил/медиа в `core/style.py`.

Что умеет, если коротко:
1. `/mute` — мут в Discord (текст + голос), `/warn` с лестницей эскалации,
   `/ban`/`/unban`, снятие, журнал в отдельный канал, история по игроку;
2. `/mutegame`/`/bangame` — мут чата и бан **на игровом сервере** по нику
   или по привязанному участнику, с авто-разбаном по сроку;
3. «события игры»: наказал сам админ в консоли/в игре → та же карточка в канале;
4. интерактивные правила (кнопки разделов, ephemeral-просмотр), медиа-карточки,
   голосовые комнаты с временным владельцем;
5. устойчивость: супервизор переподключения, health-эндпоинт, всё состояние в БД.

## 1. Требования

> Если настройку делает другой человек — отдайте ему [`DEPLOY.md`](DEPLOY.md): там
> версии зависимостей (pin), список портов по направлениям, переменные, health-ручка

| Что | Нужно |
|---|---|
| Discord | приложение-бот, право приглашать на сервер (Manage Server у того, кто приглашает) |
| Привилегированный intent | **Server Members Intent** — обязателен, без него `intents.members` не поднимется |
| Права в сервере | список ниже (§2.3). Роль бота — **выше** ролей нарушителей, ниже админских |
| Python | 3.10+ (рекомендуем 3.12) |
| Диск | ~5 МБ кода + БД (сотни КБ на тысячи записей) |
| Сеть | исходный IP порта 443 (Discord) и, если нужно, доступ к RCON-порту игры |
| Для игры | Paper/Spigot/Vanilla с `enable-rcon` + плагин мьюта, если нужен mute чата (`/tempban` — EssentialsX; ванильный `ban` есть из коробки) |

## 2. Установка: Discord-часть (5–10 минут)

### 2.1 Создать приложение
1. <https://discord.com/developers/applications> → **New Application** → имя (например «Наказание»).
2. Вкладка **Bot** → **Reset Token** → скопируйте токен. Это секрет: в чат, в issue, в git — нет.
3. Там же включить **Server Members Intent** (Privileged Gateway Intents). Без него
   бот не будет знать список участников, и `/mute` не сможет ничего выдать.
   **Message Content Intent включать не нужно** (и не стоит): текстовые сообщения
   бот не читает, команды — только slash.
4. (Опционально) **Public Bot** выключить, чтобы лишние не приглашали.

### 2.2 Файлы
```bash
unzip discord-modbot.zip && cd discord-modbot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp config.json.example config.json      # и вписать token (или использовать env, §3)
python bot.py --check                   # конфиг читается, команды собираются?
```
`--check` не требует токена и сети: загружает все cog'и, печатает список команд и
гасит фоновые циклы. Если там ошибка — чиним до запуска (например кривой JSON).

Строки `PyNaCl is not installed, voice will NOT be supported` и то же про `davey`
в логе подавлены намеренно: бот не подключается к войсу (он выдаёт таймауты и
права), нужды в этих библиотеках нет. Настоящие предупреждения discord.py
(права, сеть, перезаподключение) остаются видимыми.

### 2.3 Пригласить бота
Scope'ы: `bot applications.commands`. Наборы прав (готовая ссылка):
```
https://discord.com/oauth2/authorize?client_id=ВАШ_APPLICATION_ID&scope=bot+applications.commands&permissions=1099784350740
```
Это: View Channels, Send Messages, Read Message History, Manage Messages,
Embed Links, **Manage Roles**, **Moderate Members**, **Mute Members**, Ban
Members, Manage Channels. Позиция роли бота: Settings → Roles → перетащить выше
ролей тех, кого будете мутить/банить (иначе Discord ответит «Missing Permissions», а
наш `guard` лучше — см. §11).

### 2.4 Первый запуск
```bash
export DISCORD_TOKEN='...'      # или вписать в config.json
python bot.py                   # ctrl+c — корректная остановка
```
В логе вы должны увидеть:
- `slash-команды синхронизированы: /ban, /bangame, ...` (команды появятся в Дискорде
  в течение ~1 минуты, кэш клиента обновляется сам);
- `health-сервер на :8080 (/, /healthz) ...` — если хост дал `PORT` или вы поставили
  `keepalive: true` (§4.2);
- `gamefeed: выключен (...)` — это нормально, пока не включали (§6).

## 3. Конфиг: файл и переменные

`config.json` не обязателен: всё, что нужно для старта, — токен из окружения.
Приоритет: **env → config.json → значения по умолчанию в `core/config.py`**;
а настройки, заданные slash-командами, перекрывают `config.json` для своего сервера
(они лежат в таблице `guild_config`, `null/0/""` = «наследовать из файла»).

| Переменная | Действие |
|---|---|
| `DISCORD_TOKEN` | токен бота; перекрывает `token` из файла |
| `PORT` / `WEB_PORT` | если заданы и `keepalive: "auto"` — бот поднимает `GET /healthz` на этом порту |
| `MC_RCON_PASSWORD` | только для `tools/mc_probe.py`, чтобы не светить пароль в истории |

Ключи `config.json` (см. также пример в файле):

| Ключ | Смысл |
|---|---|
| `db_path` | путь к SQLite, по умолчанию `data/modbot.sqlite3` |
| `log_channel_id` | канал отчётов о наказаниях (или `/modsettings канал_логов`) |
| `mute_role_id` | роль для «legacy»-мута, если нет прав на timeout (§5.4) |
| `dm_target` | слать нарушителю ЛС |
| `default_reason` | причина по умолчанию |
| `feedback_hint` | строка-подсказка под событием в карточке (markdown-ссылки работают) |
| `dry_run` | тренировка: карточки пишем, ничего не меняем |
| `drivers.active` | `discord_voice` или `rcon` |
| `drivers.rcon.*` | host/port/password/timeout + шаблоны команд (§6) |
| `warn_thresholds` | лестница: `{"warns":3,"action":"mute","duration":"1h"}` |
| `reconnect_delays` | паузы супервизора, сек (по умолчанию `[5,15,30,60,120,300]`, потолок 900) |
| `reconnect_attempts` | `0` = перезапускать вечно |
| `reconnect_reset_after` | после стольких секунд healthy-аптайма счётчик пауз сбрасывается |
| `keepalive` / `keepalive_port` | `auto`/`true`/`false` и порт при отсутствии `$PORT` |
| `sync_guild_id` | id **вашего** сервера: команды грузятся только в него — видно сразу, без глобального лимита и часа на распространение. Пусто = глобально (тогда на других серверах бота команды тоже появятся). Можно и `DISCORD_SYNC_GUILD` |
| `gamefeed` | события наказаний из игры (§6.4) |

Аргументы запуска: `--config <путь>`, `--check` (проверить конфиг и команды, не
подключаясь), `--once` (выход при первом падении — для systemd/docker, §7.1),
`--diagnose` (один заход в Discord: под каким ботом я, в каких серверах, принял ли
Discord мои команды — вывод «почему /ban не виден»), `--verbose`.

## 4. Первый час в Discord: что нажать

### 4.1 Диагностика прав
```
/whoami
```
Показывает сервер, бота, флаги (mute/timeout/ban/roles), канал логов, активный
игровой драйвер (и «не настроен», если не задан), число активных наказаний,
health-эндпоинт. Это первая проверка после деплоя.

### 4.2 Настроить сервер
```
/modsettings канал_логов:#наказания        роль_мута:@Muted        драйвер:rcon
             лд:вкл  тест:выкл  подсказка:Апелляция — [тикеты](https://…/tickets)
```
- `роль_мута` нужна **только** как запасной путь: если права `Moderate Members` нет,
  бот вместо timeout выдаст роль + запреты по каналам (см. §5.4). Роль должна быть
  ниже роли цели;
- `тест:вкл` = dry_run для этого сервера: карточки в канал идут, реальных изменений нет.
  Удобно, чтобы показать админам, «как будет выглядеть».

### 4.3 Пороги варнов
```
/warnconfig уровни:"3=mute:1h, 5=mute:24h, 8=ban:3d"
/warnlevels
```
Действия: `mute`, `mutegame`, `bangame`, `ban`. Сроки — как в командах (`1h`, `3d`, `perm`).
Варн с собственным сроком (`/warn ... срок_дней:30`) перестаёт влиять на эскалацию
после истечения; варны без срока сгорают через 90 дней.

### 4.4 Правила и карточки (опционально, но красиво)
```
/rules add название:"Общие правила" эмодзи:📕 цвет:bordeaux текст:"первый абзац\n\nвторой..."
/rules import файл:rules.example.json заменить:выкл     # JSON-шаблон идёт с ботом
/rules config канал_меню:#правила канал_жалоб:#жалобы роль_помощи:@Дворецкие кнопка_канал:#домовой-чат
/rules publish канал:#правила
```
Карточка `[ПРАВИЛА СЕРВЕРА]` остаётся одна: кнопки разделов открывают текст
**ephemeral-сообщением** (его видите только вы; в канале не спам и не «выбранные
варианты» от чужих кликов), `◀ ▶` листают страницы, `≡` возвращает список.
`/rules refresh` перерисовать, `/rules list|remove <slug>` — управление.

```
/photo post заголовок:"Фотография" подпись:".." картинка:<файл> цвет:cyan канал:#новости закрепить:выкл
```
Аналог референсной «Фотографии»: `[ФОТОГРАФИЯ]` + крупная картинка.
`/photo attach сообщение:<ссылка> картинка:<файл>` докидывает картинку в уже
выложенную карточку бота.

### 4.5 Голосовые комнаты (из референса «Погладить камушек»)
```
/voice config канал_триггер:#Погладить камушек категория_комнат:Личные категория_публичных:Публичные
```
- зашёл в триггер → создалась `🔒 Ник`, у вас права мьют/глушение/перемещение +
  `Manage Channel` (впустить гостей); чужим `Connect/View Channel = нет`;
- в публичных комнатах владелец первый вошедший; ушёл — права снимаются и
  переходят следующему;
- пустая комната удаляется фоном (не раньше 60 с после создания);
- `/voice rooms` — список и владельцы, `/voice take` — забрать комнату себе,
  `/voice config выключить:вкл` — отключить модуль.

Команды видны участникам с правами сервера: `/mute`-группа требует Manage Server +
Moderate Members, `/ban` — Ban Members, `/rules publish|add|import|config|refresh`
и `/modsettings` — Manage Server, `/photo` — Manage Messages, `/voice config|rooms` —
Manage Server (+ Moderate Members для gamemode-наказаний).

## 5. Наказания в Discord: что происходит под капотом

### 5.1 `/mute` — основной инструмент
Бот ставит **Modern Timeout** (`member.edit(timed_out_until=…)`): режет и текст, и
голос по всему серверу, нарушитель не снимет его сам, и он не пропадает, если бот
упал. В карточке это подпись `timeout (текст + голос)`.

Срок: `10m/30m/1h/3h/6h/12h/1d/3d/7d/14d/30d/perm` или своё `90m`, `1h30m`, `2д`.
Максимум, который умеет Discord, — **356 дней**; `perm` таймаутом не делается,
поэтому для `perm` бот идёт путём §5.4 и требует роль.

### 5.2 `/warn` — копится и эскалирует
Запись заводится в `cases`, карточка в канал, нарушителю — ЛС (если включено).
Достигнут порог из `warn_thresholds`/`/warnconfig` → автоматически выдаётся
`mute`/`mutegame`/`bangame`/`ban` (в карточке — отметка `Автонаказание`).
Срок варна (`срок_дней:`) — только внутренний: влияет на эскалацию, ничего не
блокирует. Снятие — `/clearwarns` (все или `номер:` одной).

### 5.3 `/ban`, `/unban`
`/ban цель срок` — бан в Discord, `срок:perm` навсегда, иначе авто-разбан по
истечении (фоновый цикл снимет). `/unban id:` работает и для тех, кто уже вышел с
сервера (нужен числовой ID). Осторожно: бан в Discord **не** банит в Minecraft —
для игры `/bangame` (§6.3).

### 5.4 Legacy-путь, если прав на timeout нет
Если Discord отверг timeout (`Moderate Members` не выдано), бот:
1. выдаёт роль из `mute_role_id` / `/modsettings роль_мута` (она должна быть
   **ниже** роли цели и **выше** @everyone, иначе Discord запретит выдачу);
2. проставляет запреты `send_messages/add_reactions/create_public_threads` в
   текстовых каналах и `connect/speak/use_voice_activation` в голосовых;
3. запоминает тронутые каналы в `mute_overwrites`, а `/unmute` возвращает их в
   inherit. Это «запасной» вариант: он грубее timeout, сам не истекает (обычные сроки
   фоном снимаются), и для `perm`-мута это единственный способ — Discord не умеет
   бессрочный timeout.

### 5.5 Снятие и журнал
`/unmute цель|номер` — снимает и timeout, и роль, и запреты по каналам; для игровой части —
`/unmutegame номер`. `/modlog действие:` фильтрует `mute|mutegame|bangame|warn|ban`,
`/history цель` — всё по игроку с числом активных варнов, `/case номер снять:вкл` —
карточка и снятие «этого конкретного» наказания.

## 6. Minecraft: что и как настраивается

### 6.1 Драйверы
`drivers.active` выбирает, чем «наказывать в игре»:
- `discord_voice` (по умолчанию) — **server deafen в Discord**: глушит голос, если
  голос игры идёт через Discord-войс (типично для MC-сообществ). Доступа к серверу
  не надо вообще; мут чата/бан не умеет;
- `rcon` — консоль самого сервера: чат-мут, бан, кик-подобные, уведомления. Нужен
  доступ к RCON и правильные названия команд вашего плагина.

### 6.2 Включить RCON и проверить связь
`server.properties` (Paper/Spigot/Vanilla), рестарт сервера:
```
enable-rcon=true
rcon.ip=127.0.0.1        # наружу не выставлять! см. §12
rcon.port=25575
rcon.password=<длинный случайный пароль>
```
Проверка с той же машины, где бот:
```bash
MC_RCON_PASSWORD='<пароль>' python tools/mc_probe.py --host 127.0.0.1 --port 25575
# или: python tools/mc_probe.py --port 25575 --password '<пароль>' --cmd "ess version"
```
Скрипт использует то же рукопожатие, что и бот (Minecraft отвечает на auth ОДНИМ
пакетом, Source — двумя; обе формы поддерживаются). Код 0 — можно включать драйвер,
1 — написано почему (порт закрыт / пароль / таймаут).

### 6.3 Настроить `config.json`
```jsonc
"drivers": { "active": "rcon",
  "rcon": {
    "host": "127.0.0.1", "port": 25575, "password": "<...>", "timeout": 5,
    "mute_cmd":      "tempmute {target} {duration} {reason}",   // EssentialsX
    "mute_perm_cmd": "mute {target} {reason}",                  // без {duration}
    "ban_cmd":       "tempban {target} {duration} {reason}",
    "ban_perm_cmd":  "ban {target} {reason}",
    "unmute_cmd":    "unmute {target}",
    "unban_cmd":     "pardon {target}",
    "notify_cmd":    "tell {target} [модерация] {reason}",      // варн в игру
    "query_cmd":     "list"
  } }
```
Плейсхолдеры: `{target}` ник/UUID из `ник:`, `{duration}` — вид, который ждут
плагины (`30m`, `1h30m`, `7d`), `{minutes}`/`{seconds}` числа, `{nick}`/`{id}`
сторона Discord, `{reason}` причина. Несколько команд в одном шаблоне разделяются
`;` (например `"mute_cmd": "tempmute {target} {duration} {reason}; tell @Admins …"`).

Команды:
```
/bangame ник:BadSteve срок:7d причина:"дюп"      # только по нику, без @участника
/mutegame цель:@Игрок срок:1h                     # ник возьмём из /gamelink
/gamelink цель:@Игрок ник:STEVE2026               # привязка (одна на драйвер)
/unbangame номер:12                                # снять то, что выдали
```
- `цель:` и `ник:` взаимозаменяемы, достаточно одного; оба — приоритет у `ник:`;
- без плагина у вас ваниль: `ban`/`pardon`/`kick` есть, `tempban`/`tempmute` —
  **только EssentialsX или аналог**, иначе `mute_cmd` вернёт ошибку консоли
  (бот честно покажет это в карточке);
- бан по нику в offline-mode/без UUID обходится переименованием: в `ник:` можно
  вписать UUID, `{target}` подставит его как есть;
- у `discord_voice` «ника из игры» нет — на попытку `ник:` без участника он
  ответёт «бан по нику игры недоступен — отметьте участника Discord» и **не**
  оставит висячую запись.

### 6.4 События игры: модератор наказал сам
Бот может писать в канал и то, что выдал не он (`core/gamefeed.py`). Выключено по
умолчанию:
```jsonc
"gamefeed": {
  "enabled": true, "source": "log",
  "log_file": "/srv/minecraft/logs/latest.log",
  "interval_s": 5, "poll_cmd": "banlist", "poll_action": "ban",
  "patterns": null
}
```
- **`source: "log"`** — бот дочитывает хвост файла лога. Работает, только если бот
  и сервер на одной машине (или файл доступен по сети). Первый проход историю не
  льёт, усечение/ротация файла переживаются. Разбираются:
  `… issued server command: /tempban BadSteve 7d ксы`, `/ban`, `/pardon`,
  `/tempmute`, `/mute`, `/warn`, `/unmute` и рассылки плагинов («X was banned by Y
  for 3 days», «X был временно забанен на 2 дня по причине: …»), срок в формах
  `7d`, `2 дня`, `1h30m`;
- **`source: "rcon"`** — периодический опрос `poll_cmd`: список сравнивается с
  прошлым снимком (первый снимок — только база сравнения, без карточек); появился →
  бан, исчез → «снято» и **закрытие** активной записи бота;
- защита от дублей: окно эха 120 с (то, что отправил сам бот, из лога не
  заведётся — движок помечает «это я»), хэш строки 10 мин, не более 5 событий за тик;
- `/gamefeed status` — включён ли, что читает, сколько паттернов рабочие/сломанные;
  при старте бот пишет в лог предупреждение, если путь до лога недоступен;
- `/gamefeed try строка:"…"` — разбор конкретной строки. Не сошлось → добавьте
  паттерн в `gamefeed.patterns`:
  `{"name":"мой плагин","action":"ban","regex":"…(?P<nick>\\w{1,16})…(?P<duration>…)?…(?P<reason>.+)",
    "permanent": false}` — группа `nick` обязательна, ещё можно `duration`, `reason`,
  `actor`; действия: `ban/tempban/mute/tempmute/warn/kick/pardon/unmute/unban`.

Ограничение метода: если плагин пишет наказание только в свою БД и ничего не
пишет в лог/консоль — нужен источник под его хранилище (скажите плагин — добавим),
либо свой `poll_cmd` с его списком.

### 6.5 Если голос игры идёт через Discord
Тогда достаточно `discord_voice`: `/mutegame` включит server deafen, `/unmutegame`
снимет. В `drivers.discord_voice.quarantine_role_id` можно указать роль, которую
бот будет навешивать дополнительно (не обязательно).

## 7. Деплой: четыре рабочих варианта

### 7.1 VPS/dedicated + systemd (рекомендую, если есть машина)
`/etc/systemd/system/modbot.service`:
```ini
[Unit]
Description=Discord moderation bot (Minecraft)
After=network-online.target
Wants=network-online.target

[Service]
User=modbot
WorkingDirectory=/opt/discord-modbot
EnvironmentFile=/etc/modbot.env       # там DISCORD_TOKEN=<токен>  (или Environment=DISCORD_TOKEN=...)
ExecStart=/opt/discord-modbot/.venv/bin/python bot.py --once
Restart=always
RestartSec=10
Nice=10
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/discord-modbot/data

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now modbot
journalctl -u modbot -f           # live-логи
```
`--once` обязателен в этом варианте: перезапуском рулит systemd, а не наш
супервизор (иначе два «случайных» интервала перезапуска).

### 7.2 Docker / docker compose
```bash
cd discord-modbot && docker build -t modbot . && docker run -d --name modbot \
  --restart unless-stopped -e DISCORD_TOKEN=... -v $PWD/data:/app/data modbot
```
`docker-compose.yml`:
```yaml
services:
  modbot:
    build: .
    restart: unless-stopped
    environment: [DISCORD_TOKEN=${DISCORD_TOKEN}]
    volumes: ["./data:/app/data"]
    ports: ["8080:8080"]          # только если включаете keepalive в контейнере
```
Если игра на той же машине и нужен `source: "log"` — монтируйте лог:
`-v /srv/minecraft/logs:/logs:ro` и `gamefeed.log_file=/logs/latest.log`.

### 7.3 Порты: что прокидывать

| Направление | Порт | Нужно? |
|---|---|---|
| бот → `wss://gateway.discord.gg` | исх. TCP 443 | обязательно |
| бот → `https://discord.com/api/v10` | исх. TCP 443 | обязательно |
| бот → `cdn.discordapp.com`/`media.discordapp.net` | исх. TCP 443 | только для `/rules import` (бот читает файл вложения сам) |
| бот → `rcon.ip:rcon.port` игры | исх. TCP 25575 | только с `drivers.active: "rcon"`; вход на стороне игры разрешить по IP бота, наружу порт не публиковать |
| кто-то → бот | вход TCP `$PORT` | только health-эндпоинт (`GET /healthz`), нужен чтобы хостинг не усыплял контейнер |
| игра → бот, 25565, Discord-войс (UDP) | — | не нужно |

### 7.4 Бесплатные PaaS (Render / Railway / Fly.io)
- Build: `pip install -r requirements.txt`, Start: `python bot.py` (или `web: python bot.py`
  — Procfile есть). Секрет `DISCORD_TOKEN` — в Variables.
- **Сон — главная опасность**: хосты усыпляют контейнер без HTTP-трафика, и никакой
  reconnect не поможет (процесс стоит). Бот поднимает `GET /healthz`, если хост дал
  `PORT` (`keepalive: "auto"`, можно `"true"` + `keepalive_port`); повесьте внешний
  пинг на `https://<ваш-хост>/healthz` раз в 5 минут.
  JSON отвечает `status`, `bot`, `gateway_latency_ms`, `guilds`, `members`,
  `active_punishments`, `uptime_s`; код `503`, пока бот не поднялся.
- **Эфемерный диск**: при пересборки/рестарта контейнера `data/` обнуляется →
  теряются варны, привязки ников, правила; mount volume/диск обязателен (Render
  Disk, Railway Volume, Fly Volumes), иначе `db_path` на внешнюю БД.
  Discord-таймауты и Discord-баны при этом не теряются — они на стороне Discord.
- **Исходящий IP** на фри-тарифах меняется → RCON-доступ с такого хоста к вашему
  серверу — плохая идея (и RCON без шифрования). Либо держите бота рядом с игрой,
  либо используйте туннель/VPN, либо остаётесь на `discord_voice` (он требует
  только доступа к Discord).

### 7.5 Обновление версии
```bash
cp data/modbot.sqlite3 data/backup-$(date +%F).sqlite3   # сначала БД!
# замените код из нового архива, не трогая config.json и data/
source .venv/bin/activate && pip install -r requirements.txt
python bot.py --check && python test_offline.py && python test_features.py
```
Схема БД мигрирует сама (`CREATE TABLE IF NOT EXISTS`), откат — вернуть старый код
и бэкап БД.

## 8. Справочник команд

| Команда | Права | Что делает |
|---|---|---|
| `/mute цель срок причина тихо` | Manage Server + Moderate Members | timeout (текст+голос) или legacy-путь; `perm` — только через роль |
| `/unmute цель номер причина` | то же | снять мут/игровой мут, вернуть каналы и роль |
| `/mutegame цель ник срок причина тихо` | Manage Server + Moderate Members | заглушить в игре (rcon `mute_cmd`) или deafen в Discord |
| `/unmutegame номер` | то же | снять игровой мут тем же драйвером |
| `/warn цель причина срок_дней` | то же | варн + эскалация; в игру — `notify_cmd` |
| `/warnconfig уровни`, `/warnlevels` | Manage Server | пороги `3=mute:1h, 5=ban:3d` |
| `/clearwarns цель номер` | Manage Server + Moderate Members | снять варны (все/один) |
| `/ban цель срок причина` | Ban Members + Moderate Members | бан в Discord, `perm` навсегда |
| `/unban id` | Ban Members | разбан (и для покинувших сервер) |
| `/bangame цель ник срок причина` | Manage Server + Moderate Members | бан **в игре** (`ban_cmd`) |
| `/unbangame номер` | то же | разбан в игре (`unban_cmd`) |
| `/modlog действие лимит цель` | Manage Server + Moderate Members | последние наказания |
| `/history цель лимит` | Manage Server + Moderate Members | всё по игроку + счётчик варнов |
| `/case номер снять причина` | Manage Server + Moderate Members | карточка записи / снять её |
| `/gamelink цель ник` | Manage Server + Moderate Members | привязать ник игры к участнику |
| `/rules publish канал` | Manage Server | выложить/обновить карточку-меню правил |
| `/rules add название текст эмодзи цвет` | Manage Server | раздел правил (длинное → страницы) |
| `/rules import файл заменить` | Manage Server | загрузить JSON (`rules.example.json`) |
| `/rules config …` `list` `remove` `seed` `refresh` | Manage Server | канал меню/жалоб/роль/кнопка, список, удаление, из файла, перерисовать |
| `/photo post …` / `/photo attach …` | Manage Messages | медиа-карточка; докинуть картинку |
| `/voice config …` / `rooms` — Manage Server; `/voice take` — любые | комнаты: триггер и категории, список, забрать себе |
| `/gamefeed status` / `try строка` | Manage Server | состояние потока событий игры; разбор строки лога |
| `/modsettings …` | Manage Server | канал логов, роль мута, драйвер, ЛС, dry_run, подсказка |
| `/whoami` — Manage Server; `/ping` — все | диагностика |

Сроки везде: `10m 30m 1h 3h 6h 12h 1d 3d 7d 14d 30d perm` + свободный ввод
(`90m`, `1h30m`, `2д`, `1нед`). Ограничение Discord — 356 дней; больше — `perm`.

## 9. Мониторинг и логи

- **`GET /healthz`** — см. §7.3 (`status: ok|starting`, латентность шлюза, число
  серверов/участников, активные наказания, uptime). `503`, пока бот не готов:
  удобно как readiness-пробу.
- **`/whoami`** — что бот «видит» прямо сейчас: права, канал логов, драйвер
  (+ метка «не настроен»), число активных наказаний, состояние health-сервера.
- **`/gamefeed status`** — включён ли поток, что читает (`offset` по файлу лога),
  рабочие/сломанные паттерны, последние события, размер окна дедупа.
- **`/voice rooms`** — кто сидит в комнатах и у кого права владельца.
- Лог-уровень: `--verbose` включает DEBUG у discord.py. Что вы увидите в обычном
  режиме (эти строки и есть «норма»):
  - `slash-команды синхронизированы: /ban, /bangame, …` — команды готовы;
  - `health-сервер на :8080 (/, /healthz) — пингуйте его, чтобы хост не усыплял бота`
    — если health включён;
  - `gamefeed: выключен …` / `gamefeed: опрос banlist каждые N с` /
    `gamefeed: файл лога … не найден …` — что делает поток событий игры;
  - логи discord.py приглушены до WARNING (кроме `--verbose`), чтобы не шуметь;
  - `связь с Discord восстановлена без переподключения сессии` — gateway resume;
  - `связь потеряна … аптайм Nс — перезапуск через Ns (попытка K)` или
    `ПАДЕНИЕ …` — супервизор поднимает бота сам;
  - `бот остановлен штатно (Ctrl+C / SIGTERM)` — корректный выход.
- Все сообщения перезапуска — `WARNING`, а не traceback: паниковать стоит только
  при `sys.exit` («Переподключение не поможет: …» — токен/интенты).
- **Что мониторить извне**: `/healthz` (код 200 + `gateway_latency_ms`), в логе
  — число попыток подряд (растёт = сеть/хост подыхает).

## 10. Что делать, если…

| Симптом | Причина и решение |
|---|---|
| Команды есть, но появились не сразу | глобальный sync Discord распространяет до ~1 часа: поставьте `sync_guild_id:<id вашего сервера>` — тогда команды видны сразу |
| Команд нет в списке Discord, видны только чужие боты | запустите `python bot.py --diagnose`: он покажет, под каким аккаунтом бот зашёл, в каких серверах состоит и принял ли Discord его команды. Три возможных ответа: «ни в одном сервере» → пригласить ссылкой §2.3; «HTTP 403» → в приглашении не было `applications.commands` (удалить бота с сервера и пригласить заново); «принято N» → обновить клиент (Ctrl+R/перезаход) и проверить Server Settings → Integrations → бот: там должны быть оба скоупа и не должно быть ограничений по каналам |
| `/ban` не появляется сразу после починки | Discord кэширует список команд: Ctrl+R / перечтиление сервера, иногда 1–2 минуты |
| Команд нет в списке Discord | `CommandSyncFailure` в логе: Discord отверг загрузку. Новые сборки пишут точную причину (403/429/400/401) и пробуют снова в фоне (через 20 с, 1, 5, 15 мин, затем каждые 30 мин ~4 ч). Чаще всего — приглашение без scope `applications.commands`: выгнать бота и пригласить ссылкой из §2.3. Реже — 429 (не перезапускайте бота часто: каждая попытка тратит лимит на запись команд) |
| Бот перезапускается каждые несколько секунд | старая сборка считала сбой синка падением; обновитесь — теперь sync-ошибка не роняет процесс |
| `LoginFailure` / «Переподключение не поможет» | токен неверный/сброшен, или не включён Server Members Intent (§2.1) |
| `Missing Permissions` при `/mute` | у бота нет Moderate Members; нет роли выше цели; или `mute_role_id` стоит целью выше — поднимите роль бота (§11) |
| «У **N** роль не ниже моей» | защита `guard`: бот не трогает равных/старших. Иерархия ролей, не права |
| Карточка есть, а мута нет | dry_run (`тест:вкл`) включён — `/modsettings тест:выкл` |
| «Discord не умеет мут навсегда» | `perm` без `роль_мута`: задайте или используйте срок ≤356д |
| `mutegame`: «RCON: сервер недоступен/соединение разорвано» | порт/фаервол/рестарт игры; проверьте `tools/mc_probe.py`; бот сам переподключается, команда повторится |
| «/tempban» не сработал | нет EssentialsX (или другие имена команд) → поменяйте шаблоны в `drivers.rcon`, проверьте `/gamefeed try`+`--cmd` в probe |
| «бан по нику игры недоступен» | активен `discord_voice`; переключите `drivers.active:rcon` или отметьте `цель:` |
| Варны «не копятся» | срок варна истёк (`срок_дней`) или его сняли `/clearwarns`; посмотрите `/history` |
| Правила открываются «на всех» | так было со select-меню; здесь кнопки + ephemeral. Обновите карточку `/rules refresh` |
| gamefeed молчит | `gamefeed.enabled`, неверный `log_file` (бот и игра на разных машинах → `source:"rcon"`), статус и предупреждение в `/gamefeed status`/логе |
| После деплоя пропали варны/привязки | эфемерная ФС: смонтируйте том или бэкапьте `data/` (§7.3) |
| «database is locked» | второй процесс с той же БД (старый инстанс/системд+docker) → оставьте один |
| Бот «висит» после пробуждения хоста | супервизор переподключается; проверьте паузами `reconnect_delays`; для systemd-варианта — `--once` + `Restart=always` |

## 11. Иерархия ролей (частая причина «не работает»)

1. Discord → Server Settings → Roles: роль бота должна быть **выше** ролей нарушителей
   (иначе `Forbidden`, и наш `guard` это предвидит);
2. роль из `роль_мута` — **ниже** роли цели, но выше @everyone, и её должен уметь
   выдавать бот;
3. боту не нужен «Администратор»: достаточно прав из §2.3;
4. канал логов: боту нужны View/Send/Embed Links в нём; если там стоит запрет на
   ботов — карточки молча не дойдут (в логе появится `Не могу писать в канал логов …`,
   в `/whoami` канал будет помечен как недоступный).

## 12. Безопасность: короткий чек-лист

- **RCON не смотреть наружу.** `rcon.ip=127.0.0.1`/внутренний интерфейс + фаервол;
  протокол не шифруется и не имеет rate-limit. Бот, живущий отдельно от игры, должен
  идти к RCON через туннель/VPN, а не через открытый порт.
- Пароль RCON и токен — только в `config.json` (вне git, в архиве не лежит) или в
  переменных окружения; `.gitignore` уже исключает `config.json` и `data/`.
- `tools/mc_probe.py` принимает пароль из `MC_RCON_PASSWORD` — не печатайте его в
  истории shell лишний раз.
- Минимальные права бота (§2.3): не давайте Administrator — `/unban`, `/warnconfig`
  и `drivers.active` позволяют менять всё серверное.
- Slash-команды модерируют правами Discord: Moderate Members / Manage Server /
  Ban Members. Свои роли-исключения (например, «модер-бот только для @Staff»)
  настраиваются в интеграции приложения на сервере.
- Логи и health не содержат секретов; `/healthz` отдаёт только количество
  серверов/участников/наказаний и аптайм.
- `dry_run`/`тест:вкл` — безопасный режим для демонстрации настроек новичкам-админам.

## 14. Ограничения, о которых нужно знать

- Discord-бан и игровой бан — разные вещи: `ban_cmd` настраивается отдельно, и
  «разбанить всё разом» одной командой нельзя (используйте `/unban` + `/unbangame`);
- варн — состояние бота: плагин игры про него не знает (в игру уходит только `tell`);
- `source: "log"` не подтягивает историю до запуска; сторонние плагины, пишущие
  только в свою БД, видны только через их `poll_cmd` или хранилище;
- правила/карточки — обычные сообщения Discord: их может удалить кто-то с
  Manage Messages; `/rules refresh`/`/rules publish` вернут (publish обновит
  существующую карточку, а не создаст вторую);
- лимиты Discord на месте: 80 символов в подписи кнопки, 25 компонент в сообщении
  (потому в меню не больше 20 разделов), 4096 символов описания карточки
  (отсюда порезка на страницы ~1600), timeout ≤ 356 дней;
- `perm`-мут = роль + запреты: держится, пока вы не сделали `/unmute`, переживает
  перезапуск бота, но не переживает удаление роли;
- SQLite = один пишущий процесс: не запускайте два инстанса на одной базе.

## 15. Чек-лист «всё ли работает»

```bash
python bot.py --check            # конфиг и команды  → 38 строк (топы + подкоманды)

MC_RCON_PASSWORD=... python tools/mc_probe.py       # связь с игрой → код 0

systemctl is-active modbot       # или docker ps → healthy
```

В Discord: `/whoami` (все галочки зелёные, драйвер выбран) → `/modsettings тест:вкл`
→ `/mute @тест срок:10m` → карточка в канале → `/unmute цель:@тест` →
`/gamefeed status` (если игра подключена) → `тест:выкл`.
