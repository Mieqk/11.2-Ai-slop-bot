# Discord-бот модерации: муты (ДС + игра), варны, баны, отчёт в канал

Python + [discord.py](https://discordpy.readthedocs.io/) 2.x. Slash-команды,
свои права на каждый тип наказания, SQLite-хранилище кейсов, фоновое авто-снятие
истёкших наказаний и расширяемый «драйвер» для мута **внутри игры**.

> **Полная инструкция по установке, настройке, деплою и диагностике — в [`SETUP.md`](SETUP.md).**
> Для админа хостинга: [`DEPLOY.md`](DEPLOY.md) (версии зависимостей, порты по направлениям, health) и `requirements.lock.txt`.

## Деплой: что куда залить

Архив `discord-modbot.zip` = готовое приложение. `config.json` в архиве **нет**
(чтобы токен никуда не уехал): настройки берутся из `config.json.example` +
переменные окружения. Минимум от хостинга — `DISCORD_TOKEN`.

| Переменная | Что делает |
|---|---|
| `DISCORD_TOKEN` | токен бота; файл-конфиг тогда не нужен |
| `PORT` / `WEB_PORT` | хост дал порт → сам поднимается `GET /healthz` (пингуйте его, чтобы контейнер не усыпили) |

Логи в stdout, база — `./data/modbot.sqlite3`. Если бот будет банить в игре,
его исходящий IP должен иметь доступ к порту RCON (на одном сервере — просто
`127.0.0.1`, и это самый надёжный вариант). (нужен **записываемый** путь, см.
предупреждение про эфемерную ФС ниже).

**Render / Railway / любой «git-репозиторий»**
1. New Web Service → Python, build `pip install -r requirements.txt`,
   start `python bot.py` (есть и `Procfile` с `web: python bot.py`).
2. Environment: `DISCORD_TOKEN`.
3. Deploy → `https://<сервис>.onrender.com/healthz` покажет JSON со статусом,
   числом серверов и активными наказаниями. Пингуйте этот URL раз в 5 минут
   (встроенный cron Render/UptimeRobot), иначе фри-тариф усыпит контейнер.

**Docker (VPS, Fly.io, и т. п.)** — `docker build -t modbot . && docker run -d
--restart unless-stopped -e DISCORD_TOKEN=... -v $PWD/data:/app/data -p 8080:8080
modbot` (в `Dockerfile` уже заложено).

**VPS с systemd** — `ExecStart=/usr/bin/python3 bot.py --once` (супервизор в
юните делает `Restart=always`; флаг `--once` отключает двойной надзор), плюс
`Environment=DISCORD_TOKEN=...`, `RestartSec=10`.

**Первые команды в Discord** (бот должен быть на сервере с правами из чек-листа выше):
```
/whoami                          → видно ли права и канал логов
/modsettings канал_логов:#мод-лог
/rules publish канал:#правила     → меню разделов (при пустом сервере заполнится
                                   из rules.example.json — затем отредактируйте
                                   своими текстами через /rules add или /rules import)
/voice config канал_триггер:#камушек категория_комнат:Личные
```

**Проверка связи с игрой — доверять на слово не стоит:**
```bash
python tools/mc_probe.py --host 127.0.0.1 --port 25575 --password '<rcon-пароль>'
# или MC_RCON_PASSWORD=... python tools/mc_probe.py
# свои команды: --cmd "ess list bans" ; код 0 = RCON жив, 1 = не подключился
```
Прогон показывает: открыт ли порт, проходит ли авторизация (рукопожатие то же, что
у бота), что возвращает `list` и какие ники он умеет разобрать для подсказок.

**Чего здесь сознательно нет (пока):**
* **интеграции с DiscordSRV** — бот с ним уживается (у DiscordSRV свой батлер, конфликтов
  нет), но **общей базы привязок не будет**: DiscordSRV хранит связи сам, а этот бот —
  свои (`/gamelink`). Автоимпорт из его хранилища (`LinkedAccounts.json` / MySQL / SQLite)
  — отдельная задача, скажите версию и чем он хранит, добавлю;
* чтения уже выданных банов: `ban`/`pardon` в игре, сделанные не ботом, в журнал не
  попадут, и «уже забанен» перед выдачей бот не проверит;
* варнов как игрового состояния: варн живёт в этом боте, в игру уходит только
  уведомление `tell`;
* синхронизации чата MC ↔ Discord (это и есть работа DiscordSRV, не дублируем).

**Важно про бесплатный хостинг:** база SQLite на эфемерной файловой системе
хостинга живёт до первой перезаписи контейнера — после рестарта хоста история
варнов и привязки SteamID обнулятся (дискордовские таймауты при этом живут на
стороне Discord и не теряются). Либо монтируйте диск (`-v $PWD/data:/app/data`,
Render Disk, Railway volumes), либо переносите `db_path` на Postgres.

## Что умеет

| Команда | Что делает |
|---|---|
| `/mute цель срок причина тихо` | Мут в Discord: текст **и** голос одним таймаутом. Срок: `10m 30m 1h 3h 6h 12h 1d 3d 7d 14d 30d perm` или своё (`90m`, `2д`) |
| `/unmute цель/кейс` | Снять мут (по цели или по номеру кейса) |
| `/mutegame цель срок причина игровой_id` | Мут внутри игры — через драйвер: глушит голос/чат на игровом сервере |
| `/unmutegame кейс` | Снять игровой мут |
| `/warn цель причина срок_дней` | Варн. На пороге накопления авто-наказание (мут/бан), варны сгорают через 90 дней |
| `/warnconfig уровни` | Свои пороги: `3=mute:1h, 5=mute:24h, 8=ban:7d` |
| `/warnlevels` | Показать пороги |
| `/clearwarns цель [кейс]` | Снять варны (все или один) |
| `/ban цель срок причина` | Бан, в т.ч. временный с авто-разбаном |
| `/unban id` | Разбан (работает и для вышедших с сервера) |
| `/modlog действие лимит цель` | Таблица последних кейсов |
| `/history цель` | Все наказания игрока + счётчик варнов |
| `/case кейс [снять]` | Карточка кейса: кто, кому, за что, до когда; может снять наказание |
| `/gamefeed status` / `try` | Состояние потока игровых событий и разбор конкретной строки лога |
| `/gamelink цель игровой_id` | Привязка Discord ↔ SteamID/UID (нужно для RCON-драйвера) |
| `/modsettings канал_логов роль_мута драйвер лд тест` | Настройка сервера прямо из Дискорда |
| `/whoami` | Диагностика: права бота, канал логов, активный драйвер, число кейсов |
| `/rules publish` | Выложить/обновить карточку-меню правил в канале |
| `/rules add` | Раздел правил: `название`, `текст`, `эмодзи`, `цвет` (длинный текст сам режется на страницы) |
| `/rules import` | Загрузить разделы JSON-файлом (см. `rules.example.json`) |
| `/rules list` `remove` `config` `refresh` | Список, удаление, канал меню/жалоб/роль помощи, перерисовка карточки |
| `/photo post` | Медиа-карточка `[заголовок]` + картинка + подпись + цвет полосы |
| `/photo attach` | Добавить картинку к уже выложенной карточке бота |
| `/voice config` `rooms` `take` | Комнаты: канал-триггер и категории, список, «забрать комнату себе» |

**Откидка в отдельный канал.** Каждый мут/варн/бан постится эмбедом в заданный
канал: нарушитель, модератор, срок, дата окончания («до скок мут»), причина и
техническая строка — что реально применилось (`timeout (текст + голос)`,
`Discord: включён server deafen`, ответ RCON и т. п.). Авто-снятие по истечении
тоже уходит в канал, но помечается как `⏱ Авто-снятие` и не спамит в ЛС.

## Установка

> **Только slash-команды**: текстовых `!команд` в боте нет (префикс — упоминание бота),
> поэтому message content intent включать не нужно. Предупреждения discord.py про
> PyNaCl/davey (голос) подавлены намеренно: бот не заходит в войс.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp config.json.example config.json     # вписать token
python bot.py --check                  # конфиг + список команд, без входа в сеть
python bot.py                          # запуск
```

Токен можно не хранить в файле: `export DISCORD_TOKEN=...`.

### Создать приложение бота
1. [Discord Developers](https://discord.com/developers/applications) → New Application → Bot → Reset Token.
2. **Privileged Gateway Intents**: включить **Server Members Intent** (боту нужно видеть участников для timeout/role).
3. OAuth → URL Generator → скоупы `bot applications.commands`, разрешения:
   `Manage Roles`, `Moderate Members`, `Mute Members`, `Ban Members`, `Manage Channels`, `Embed Links`, `View Audit Log`.
4. Пригласить бота по ссылке. Роль бота должна быть **выше** ролей нарушителей, а роль мута — **ниже** роли цели (иначе Discord не даст её выдать).

### Первый запуск на сервере
```
/whoami                       → проверить, что хватает прав
/modsettings канал_логов=#мод-лог   → теперь все кейсы падают туда
/modsettings тест:true         → тренировочный режим: лог пишем, ничего не меняем
/modsettings роль_мута:@Muted  → роль для legacy-пути (если timeout недоступен)
```

## Интерактивные правила (по референсу «Лисички»)

Одно сообщение в канале — карточка `[ПРАВИЛА СЕРВЕРА]` с **кнопками разделов**.
Нажатие открывает раздел **ephemeral-сообщением: его видите только вы**, а в
канале ничего не меняется. (Так сделано намеренно: select-меню Discord дописывает
в общее сообщение «Выбранные варианты: …», и выбор был бы виден всем.)

Внутри открытого раздела: `◀ ▶` листают страницы, `≡ к списку` возвращает меню в
то же ephemeral-сообщение, а внизу может быть кнопка-переход «Все прочитали?
Перейти в канал» — как в референсе; задаётся `/rules config кнопка_канал:#…`.

* Тексты — в SQLite (`rule_categories`), одна запись = раздел: `emoji`, `title`,
  `color`, `pages` (массив страниц). Проще всего загрузить файлом:
  `/rules import файл:rules.example.json заменить:true`, потом `/rules publish`.
  Формат: `[{ "emoji": "🔊", "title": "Голосовые каналы", "color": "amber",
  "text": "…" }, …]` — `text` можно разбить на страницы массивом `pages`.
* Разбиение на страницы автоматическое: режет по пустым строкам, потом по
  предложениям, — никогда посередине слова (лимит карточки 1600 символов).
* Подсказка снизу настраивается в `/rules config`: `канал_жалоб:#…` и
  `роль_помощи:@…` → «· есть вопрос по решению модерации — <#…> · поможет
  команда <@&…>». Ту же роль можно упомянуть в тексте правила.
* Правка регистра в названии (`"общие правила"` → `"Общие правила"`) — это
  апдейт того же раздела, а не второй раздел с тем же текстом.
* **Состояние не хранится в памяти**: открытый раздел читается из заголовка
  карточки, номер страницы — из её футера. Поэтому листание работает и после
  перезапуска бота (шаблон вью со всеми `custom_id` зарегистрирован в `setup()`).
* Разделов может быть сколько угодно, в меню показываются первые 20 (лимит
  Discord на компоненты в сообщении), и карточка об этом пишет.
* Эphemeral-карточка помечена в футере «· видите только вы» — чтобы не было
  сомнений, кто её видит.

## Голосовые комнаты (пункты 2.1 / 2.2 из правил)

`/voice config канал_триггер:#«Погладить камушек» категория_комнат:Личные
категория_публичных:Публичные`

* Вход в канал-триггер → за участником создаётся `🔒 Ник` в категории комнат,
  он там владелец: `connect/speak/stream`, `mute_members`, `deafen_members`,
  `move_members`, `priority_speaker`, `manage_channels` (без последней нельзя
  впустить гостей), остальным — `connect/view_channel = False`.
* Публичная комната: владелец — тот, кто первым в ней оказался (по факту в
  канале, а не по роли). Ушёл, а в комнате остались люди → права снимаются с
  ушедшего и переходят первому оставшемуся.
* Пустая личная комната удаляется фоновым циклом раз в минуту, но не раньше чем
  через 60 с после создания (перезаход/переезды).
* `/voice take` — забрать управление себе, если прежний владелец вышел, а бот
  этого не увидел (например, был рестарт: карта владельцев держится в памяти).
* `/voice config выключить:true` — модуль гасится, созданные комнаты остаются.

## Медиа-карточки (референс «Котёнок · Фотография»)

`/photo post заголовок:"Фотография" картинка:<файл>` — карточка `[ФОТОГРАФИЯ]`
с крупной картинкой и подписью; `цвет:` — по умолчанию голубая полоса, `канал:` —
куда постить, `закрепить:true` — прикрепить. `/photo attach сообщение:<ссылка>
картинка:<файл>` дозагружает картинку в уже выложенную карточку бота (только
свои сообщения, только текущий канал).


## Наказания, выданные в игре (не ботом)

Если модератор забанил/замутил **на самом сервере**, в канале появляется та же
карточка, что и от команд бота: `Забанен на игровом сервере · Игрок `BadSteve``
со сроком «1 день» и футером «из игры: issued server command: …». За это отвечает
`cogs/gamefeed.py` (разбор — `core/gamefeed.py`), **по умолчанию выключено**.

```jsonc
"gamefeed": {
  "enabled": true,
  "source": "log",                       // или "rcon"
  "log_file": "/server/logs/latest.log", // для source: log
  "poll_cmd": "banlist",                 // для source: rcon
  "poll_action": "ban",
  "interval_s": 5,
  "patterns": null                       // null = дефолтные regex, или свой список
}
```

Два источника:
* **`log`** — бот дочитывает хвост файла логов сервера. Работает, только если бот
  запущен **на той же машине** (или лог доступен по сети): `offset` хранится в
  памяти, ротация/усечение файла переживаются, при первом проходе история не
  льётся — только новые строки. Понимает строки вида
  `Admin issued server command: /tempban BadSteve 7d ксы` (ваниль пишет их в лог),
  а также английские/русские рассылки плагинов («BadSteve was banned by Admin for 3 days»,
  «BadSteve был временно забанен на 2 дня»), бан по UUID (`/ban <uuid>` — UUID можно передать и в `ник:`)
  и команды `mute/warn/pardon/unmute`.
* **`rcon`** — опрос `poll_cmd` (например `banlist`) раз в `interval_s`: список
  сравнивается с прошлым снимком; новый игрок → карточка бана, исчез → карточка
  «снято», и **активная запись бота закрывается** (иначе журнал врал бы, что бан висит).
  Первый снимок — только база сравнения, карточек не будет.

Как не двоить:
* **окно эха** 120 с — то, что выдал сам бот (`/bangame`, `/mutegame`), второй
  карточкой из лога не появляется;
* хэш строки лога на 10 минут и «такое же событие за 2 минуты» — дубликаты отбрасываются;
* в журнал запись попадает с отметкой `source: game`; ник игры хранится в записи, а
  участник подтягивается по привязке `/gamelink` (если её нет — карточка всё равно
  корректная, просто без упоминания), а в ЛС уйдёт уведомление только если аккаунты
  связны через `/gamelink`.

Настройка и самопроверка:
* `/gamefeed status` — включен ли поток, что читает, сколько паттернов рабочие и сколько
  событий уже обработано; при старте бот пишет в свой лог предупреждение, если
  включено, но читать нечего (путь до логов не задан или файл недоступен)
* `/gamefeed try строка:"<вставить строку из логов>"` — показать, как парсер
  разберёт именно вашу строку. Не разобрали — добавьте паттерн в
  `gamefeed.patterns` (`(?P<nick>…)` обязательно, плюс `duration`/`reason`/`actor`)
  и проверьте той же командой: кастомных плагинов с уникальным текстом рассылки
  я угадать не могу, поэтому это конфиг, а не магия.

Ограничение, о котором стоит знать заранее: при `source: log` **история до запуска
бота не подтягивается** (читается только новое), а баны, выданные через стороннюю
веб-панель/плагин без записи в лог, не увидит ни один источник — тогда нужен
либо их API/база, либо `poll_cmd` с их списком.


## Мут в игре

«Мут в игре» — это не одна команда для всех игр, а интерфейс
[`drivers/base.py`](drivers/base.py) `BaseDriver`. Активный драйвер выбирается
глобально в `config.json` (`drivers.active`) или на сервере через
`/modsettings драйвер:...`.

В комплекте:

* **`discord_voice`** (по умолчанию) — игра говорит голосом через Discord
  (CS2, Dota 2, Rust, Minecraft + Discord VoIP и большинство других): включает
  **server deafen**, который нарушитель не может снять сам. Доступа к игровому
  серверу не требует.
* **`rcon`** — Source-RCON (CS2/CS:S/CS:GO, GMod, MTA, Rust и любой движок с
  Source RCON). Шаблон commands в конфиге, чтобы не писать код под плагин:
  ```json
  "rcon": {
    "host": "1.2.3.4", "port": 27015, "password": "rcon_pass",
    "mute_cmd":      "sm_silence {target} {minutes}",
    "chat_mute_cmd": "sm_smute {target} {minutes}",
    "unmute_cmd":    "sm_unsilence {target}"
  }
  ```
  Подстановки: `{target}` (игровой ID), `{minutes}`, `{seconds}`, `{reason}`.
  Игровой ID привязывается `/gamelink цель STEAM_0:1:12345`.

Своя игра: скопируйте `drivers/_template.py.example` →
`drivers/mygame.py`, реализуйте `resolve/mute/unmute`, `@registry.register` —
больше трогать ничего не нужно. Если `idempotent_apply = True`, бот при
рестарте/переподключении сервера заново рассылает активные муты (см.
`cogs/expiry.py`).

## Minecraft-сервер: как это устроено

Голос ванильной Minecraft нет — есть два разных «мута», и они не заменяют друг
друга:

| Что нужно | Чем делается в этом боте |
|---|---|
| Заглушить **голос** (Discord VC, SimpleVoiceChat через Discord) | `/mute` (Discord-timeout) или `/mutegame` с драйвером `discord_voice` (server deafen) |
| Запретить **писать в игровой чат** | `/mutegame` с драйвером `rcon` → команда плагина мьюта |
| Выдать **бан в игре** | `/bangame` (rcon `ban_cmd`), авто-разбан по сроку — то же rcon `unban_cmd` |
| Сообщить **варн** в игре | `/warn` сам шлёт `notify_cmd` (`tell <ник> …`), если ник привязан |

**1. Включить RCON на сервере** (`server.properties` / `paper-global.properties`):
```
enable-rcon=true
rcon.ip=0.0.0.0
rcon.port=25575
rcon.password=<длинный пароль>
```
В `config.json` → `drivers.active: "rcon"` и блок `drivers.rcon` (host/port/password +
шаблоны команд). Бот должен иметь доступ к порту: не забудьте разрешить IP бота
в фаерволе/группе безопасности.

**2. Шаблоны под Minecraft (EssentialsX):**
```json
"mute_cmd":      "tempmute {target} {duration} {reason}",
"mute_perm_cmd": "mute {target} {reason}",            # срок perm — без {duration}
"ban_cmd":       "tempban {target} {duration} {reason}",
"ban_perm_cmd":  "ban {target} {reason}",             # иначе плагин получит tempban 0
"unmute_cmd":    "unmute {target}",
"unban_cmd":     "pardon {target}",
"notify_cmd":    "tell {target} [модерация] {reason}",
"query_cmd":     "list"
```
Подстановки: `{target}` — ник в игре, `{duration}` — «30m», «1h30m», «7d»
(как просят плагины), `{minutes}`/`{seconds}` — числа, `{nick}`/`{id}` —
Discord-сторона, `{reason}` — причина. Несколько команд в одном шаблоне — через `;`.

**3a. Наказание по нику игры.** В `/mutegame` и `/bangame` оба аргумента
необязательны, но нужен хотя бы один:
* `цель:` — берём ник из привязки `/gamelink` (или просим указать `ник:`);
* `ник:` — наказание только по нику игры, участник Discord не обязателен: запись в
  журнале создаётся с пустым адресатом (`user_id = 0`), в карточке светится
  `Игрок \`Steve\``, а ЛС, разумеется, не отправляется;
* снятие (`/unbangame номер`, `/unmutegame номер`) работает по нику так же.
  Доступно драйверам с `by_nick_only` (это `rcon`); `discord_voice` честно
  откажет — в Discord-войсе «ника из игры» не существует.

  ⚠️ Бан по нику в Minecraft обходится переименованием аккаунта: в поле `ник:`
  можно передать **UUID** игрока — плейсхолдер `{target}` подставит его как есть,
  и `tempban`/`ban` по UUID от переименования не съезжает. Для офлайн-режима
  (offline-mode) UUID считаются от ника, так что там это не спасает.

**3. Связка Discord ↔ Minecraft.** Игра оперирует никами, Discord —
идентификаторами, поэтому нужен мост:
* `/gamelink цель:@Steve ник:STEVE2026` — вручную привязать ник (хранится в `game_links`);
  после этого `/mutegame`, `/bangame`, «варн в игру» ищут игрока сами.
* `/unmutegame`/`/unbangame` снимают тем же драйвером, который назначал наказание, —
  даже если админ за это время сменил `drivers.active`.
* Если на сервере стоит **DiscordSRV**, привязку можно читать из его файла
  (`_links.json`: MC-UUID ↔ Discord ID) и забыть про `/gamelink` — это отдельно
  добавляется по запросу (нужен путь к плагину и доступ к файлу/БД).

**Что пока не умеет (и может быть добавлено):** читать список банов самого
Minecraft и показывать "уже забанен" до выдачи; синхронизация в обратную
сторону (наказание, выданное в игре плагином, не попадёт в канал — только то,
что выдал бот); ретрай `warn`/`mute` при офлайн-игре — драйвер честно вернёт
ошибку, и запись в журнале пометится «не применено» и закроется, чтобы не
висеть активным.


## Как мут «реально» работает (важно понимать)

1. **Modern Timeout** Discord (`member.edit(timed_out_until=...)`) — режет и
   текст, и голос по всему серверу разом, не снимается нарушителем. Основной путь.
2. Если права на timeout не выданы, бот падает на **legacy-путь**: выдаёт роль
   мута + ставит `deny` на отправку сообщений и на вход/говорку по каналам,
   сохраняя затронутые каналы в БД, чтобы `/unmute` их откатить.
3. `mutegame` трогает только голос/чат игры и идёт через драйвер, не через timeout —
   поэтому не конфликтует с обычным мутом и снимается отдельно.

Бот **не** трогает того, кто стоит в иерархии ролей не ниже него, и самого себя —
вместо этого `/mute` ответит подсказкой, что поднять роль.

## Держит ли соединение на бесплатном хостинге

Коротко: да, и тут для этого три слоя.

1. **discord.py сам** переподключает gateway: обрыв вебсокета, `RESUME`,
   пересылка пропущенных событий — это внутри библиотеки, мелкие сетевые
   дёргания бот не замечает вовсе.
2. **Наш супервизор `run_forever()`** в `bot.py` подбирает то, что библиотека
   пережить не может: шторм DNS, `ConnectionResetError`, таймауты, собственный
   лимит попыток шлюза и случайное исключение из кода. Схема: новый объект бота
   (чистое состояние) → пауза 5 → 15 → 30 → 60 → 120 → 300 сек плюс джиттер →
   повтор. Если бот продержал `reconnect_reset_after` секунд без падения,
   счётчик обнуляется: раз в сутки падающий бот перезапускается за 5 секунд,
   а упавший сразу после старта не долбит Discord каждые две секунды.
   Любой перезапуск начинается немедленно, как только вы починили токен.
   Настройки:
   ```jsonc
   "reconnect_delays": [5, 15, 30, 60, 120, 300],
   "reconnect_attempts": 0,        // 0 = перезапускать вечно
   "reconnect_reset_after": 300    // сек аптайма, после которых счётчик сбрасывается
   ```
   Неверный токен и невыданные privileged-интенты перезапуск не лечат — по ним
   бот выходит сразу и внятно. Для systemd/Docker, которые сами поднимают
   процесс, запускайте `python bot.py --once`: тогда двойной надзор не нужен.
3. **Главная беда бесплатных хостингов — не обрыв, а сон.** Render free и подобные
   останавливают контейнер из-за отсутствия HTTP-трафика; никакой reconnect тут
   не поможет, бот просто спит и ничего не модерирует. Поэтому поднимается
   `keepalive`: HTTP-сервер с `GET /healthz`, отвечающий
   `status`, `gateway_latency_ms`, число серверов/участников, количество
   активных наказаний и uptime. `keepalive: "auto"` включает его сам, как только
   хост задаст `$PORT`; `"true"`/`"false"` — вручную. Поставьте внешний пинг
   (UptimeRobot, cron) раз в 5 минут на этот URL: контейнер не уснёт, и вы
   получите готовую точку мониторинга.

Что ещё влияет на «не рвало наказание» сильнее, чем реконнекты, и уже учтено:

* **Состояние живёт в SQLite, а не в памяти.** После подъёма `cogs/expiry.py`
  за минуту добирает всё, что просрочилось, пока бот лежал: снимает истёкшие
  муты, баны и deafen'ы, гасит старые варны. `timeout` Discord вообще держит
  сторона Discord, без бота.
* **RCON переподключается молча.** Игровой сервер закрывает idle-соединение
  раньше, чем бот очнётся, — команда ушла бы в мёртвый сокет и «успешно» ничего
  бы не сделала. Обрыв теперь ловится при чтении, сокет выбрасывается, и команда
  повторяется поверх свежей авторизации (сценарий покрыт тестом).
* **Рестарт игрового сервера не стирает муты**: у драйвера с `idempotent_apply`
  фоновый цикл раз в минуту заново рассылает активные наказания в игру.

## Оформление отчётов и как это перекрасить под себя
Идея вёрстки (цветная полоса, одна строка события, компактная таблица, аватар
справа) — общая для модер-ботов; **тексты, заголовки и цвета здесь свои** и лежат
одним блоком `BRANDING` в [`core/audit.py`](core/audit.py):

```
┃ ОТЧЁТ МОДЕРАЦИИ                        ┃ терракотовая — выдано
│ Мут выдан · @Arab_Sheih               ┃ янтарная     — варн
│ **мут**                                ┃ зелёная      — снято / истекло
│ Не согласны с наказанием — обсудите…  ┃ справа — аватар
│ КЕМ `kotte00` · СРОК `1 час` · ПРИЧИНА `1.2.1`
└ применено: timeout (текст + голос)     ← техническая строка мелким шрифтом
```
Номер записи и «до скок истечёт» в карточку не пишутся — не нужно шуметь: номер
виден модератору в ответе команды (`№7`) и в `/modlog`, а срок стоит в самом
наказании Discord (и в `/case номер:` если нужен разбор).

* Меняется правкой блока в `core/audit.py`: `REPORT_TITLE`, `DM_TITLE`, `COLOR_*`,
  `COL_*` (имена колонок), `ACTIONS` (что писать в строке события по каждому
  наказанию) и `HINT_*` (подсказки). Один блок — остальной код не трогается.
* Подсказку под событием админ ставит свою: `/modsettings подсказка:Апелляция — [тикеты](https://…)` —
  markdown-ссылка остаётся кликабельной, строка попадает и в канал, и в ЛС.
* СРОК пишется словами («1 час 30 минут», «7 дней», «навсегда»), ДО — discord-таймстемпом
  («через 6 часов», по наведению — точная дата).
* Ник/модератор/причина — в `inline code`; значения одного поля = одна строка.
* У ЛС-сообщений нарушителю тот же макет, но заголовок `НАКАЗАНИЕ НА СЕРВЕРЕ` и колонка КЕМ только там, где она неочевидна (варн).

## Хранилище и надёжность

`data/modbot.sqlite3`, таблица `cases` (id, guild, user, moderator, action,
reason, issued/expires/lifted, extra JSON) + `mute_overwrites` (каналы,
задети legacy-мутом, для отката) + `guild_config` (настройки сервера) +
`game_links` (Discord ↔ игровой ID).

Фоновый цикл раз в минуту: снимает истёкшие муты/мута-в-игре/баны, помечает
старые варны сгоревшими, заново применяет игровые муты после рестарта.
Прерванный запуск ничего не ломает: состояние живёт в БД, а не в памяти.

## Частые проблемы

| Симптом | Причина |
|---|---|
| «роль не ниже моей» у админа | Роль бота ниже цели: Discord → Settings → Roles, поднимите бота |
| `▶` не листает правила | Карточку пересоздали вручную без view — `/rules refresh` или `/rules publish` |
| Гость не заходит в личную комнату | Владелец должен дать каналу доступ сам (`manage_channels` у него есть) |
| В канале логов пусто | `/modsettings канал_логов:#мод-лог` + право писать боту |
| «⚠️ нет прав Modern Timeout» в отчёте | Не выдано `Moderate Members` → бот перешёл на роль/разрешения |
| `/mutegame` → «не знаю SteamID» | Для `rcon`-драйвера привяжите ID: `/gamelink` |
| RCON: сервер недоступен | Бот хостится вне сети игры: нужен белый IP/порт, файрвол |
